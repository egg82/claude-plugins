# Catalog

One entry per plugin, then the stances. Each line says what the item does, what it needs to be
useful, and which signals in your own Claude Code history or setup suggest you would want it.
A plugin installs whole; the lines under it are the parts you would be getting.

Cross-references are listed at the bottom (generated by `tools/xref.py`). Take them into account:
a hook whose message names a skill is only half useful without that skill, and a stance that
tells Claude to load a skill does nothing if the skill is not installed.

To have your own Claude pick for you, see [START-HERE.md](START-HERE.md).

"Needs: nothing" means nothing beyond Claude Code, `bash` and `python3` (every hook is a bash
script that calls python3).

## Plugins

### engineering

Keep an agent-built codebase well designed: structural gates with held ledgers, tests proven able to fail, bug hunts proven by running them, API contracts.

- `agentic-engineering` (skill) — structural gates (function/file size, type-check ratchets), held ledgers that may only shrink, a fit pass before adding a new system, tests proven able to fail. Needs: a repo with CI or a test suite; the templates are Python/pytest. Signals: agents write most of your code; a file or function has grown into a god object; an agent loosened a threshold to get CI green.
- `api-contract-first` (skill) — give an HTTP API schemas a client can generate typed objects from: one schema per resource, typed errors, constrained params. Needs: an HTTP API you own (examples lean FastAPI/pydantic). Signals: routes returning bare `dict`; generated clients full of `Object`; you run FastAPI or OpenAPI codegen.
- `bug-hunt` (skill) — hunt real defects in a repo and prove each by execution, with file:line pointers; covers correctness, performance, security, resilience, UI. Needs: a repo you can run; subagents help. Signals: you ask "what's broken here"; you file issues on projects; you have asked for a perf or security pass.
- `hunt-sweep` (skill) — the standing multi-lane bug/perf/security hunt over a whole repo with duplicate hunters, then findings landed test-first. Needs: subagent fan-out and a sizeable token budget (a Max plan or equivalent); builds on `bug-hunt`. Signals: transcripts show subagent spawns on code review or hunting; you maintain a repo of real size.
- `verification-gate` (skill) — write or audit tests, lint, hooks or CI so they fail when the code is wrong and stay quiet when it is fine. Needs: nothing. Signals: you have had a check pass that should not have; flaky tests; you are adding tests to untested code; a command reported success that turned out wrong.
- `held-ledger-raise-gate` (hook, Stop; **holds the end of a turn once per session**) — blocks once when a repo touched this session has a held-ledger JSON (`tools/held/*.json` or `*_held.json`) whose counts went up against the merge-base. Needs: git, and the held-ledger pattern from `agentic-engineering`. Signals: you use ratchet files for violations, or want to; otherwise it never fires.

### vetting

Decide whether to adopt something: orient in an unfamiliar repo, vet a third-party project, judge a hyped AI tool, compare self-hosted apps.

- `cc-tool-vet` (skill) — verdict on a hyped Claude Code tool or skill collection: adopt, steal the idea, or skip, judged against what you already have. Needs: nothing. Signals: you paste GitHub links of agent tooling and ask whether it is worth it.
- `repo-orient` (skill) — map of the few load-bearing files in an unfamiliar or LLM-bloated repo. Needs: nothing. Signals: you start work in repos you did not write.
- `repo-vet` (skill) — go/no-go on trusting a third-party repo: maintenance health, claims vs reality, AI-slop. Needs: nothing (web access helps). Signals: you evaluate OSS projects or dependencies before adopting; you self-host things.
- `selfhosted-options` (skill) — research and recommend a self-hosted app for a job. Needs: web search. Signals: you run a homelab, Docker or Kubernetes apps, the arr stack.

### writing

Prose that doesn't read as model-written; READMEs, PR descriptions and wiki pages a stranger can read cold.

- `confluence-kb-docs` (skill) — wiki or Confluence pages: how-tos, KB articles, overviews, BLUF-first. Needs: a Confluence MCP server to publish; drafting needs nothing. Signals: you write wiki or KB pages.
- `doc-cold-read` (skill) — adversarial cold read of a README, ADR or spec for leaked deliberation, shorthand and false claims. Needs: nothing (subagents help). Signals: you write READMEs or docs; docs written by Claude read like a conversation dump.
- `pr-description` (skill) — PR/MR description with Why, How (and what was verified), a small flow diagram, screenshots for UI; publishes with `gh` or `glab`. Needs: `gh` or `glab`. Signals: you open PRs or MRs from Claude sessions.
- `repo-readme` (skill) — write a README or docs tree a human wants to read. Needs: nothing. Signals: you write READMEs or docs; your repos carry boilerplate "Getting started" text.
- `writing-craft` (skill) — how to write or revise any prose so it does not read as model-written; UI copy, fiction, emails, naming, non-English text. Needs: nothing. Signals: you ask Claude for emails, posts, copy, lore or dialogue; you say something "sounds like AI".

### frontend

Web UIs that look alive without lying, rendered and looked at before they're called done; promo videos of a real site.

- `headless-render` (skill) — render HTML to a screenshot and look at it, on a host with no browser (podman + Firefox recipe, or a real browser if you have one). Needs: podman or a browser; write an `instance.md` beside it for your host. Signals: Claude produces HTML you view; you run on a server or container host without a browser.
- `promo-video` (skill) — scripted promo video of a real web app, rendered to mp4 with no manual recording. Needs: node, Playwright and ffmpeg. Signals: you ship a web app and want a launch or demo video.
- `ui-craft` (skill) — take a data-heavy UI from "fine" to good without trading away honesty (labels, units, no fake figures). Needs: nothing. Signals: you build dashboards, stats pages or leaderboards.
- `html-render-gate` (hook, Stop; **holds the end of a turn once per session**) — if the session wrote HTML and never took a screenshot, read an image or drove a browser, says so before ending. Needs: nothing to run; useful with `headless-render`. Signals: Claude writes HTML pages, dashboards or artifacts for you.

### game-dev

Game design method with evidence labels, and choosing sound you can't hear.

- `audio-curation` (skill) — pick, cut, level and place sound effects and music when you cannot hear them, with a listening page for a human to judge. Needs: a human with ears; SFX or music packs. Signals: you build a game or app with sound.
- `game-design` (skill) — evidence-labelled method for onboarding, feedback, pacing, playtests, legibility and game screens. Needs: nothing. Signals: you build a game or gamified app.

### shell-safety

Blocks shell commands whose result would lie silently, lints scripts as they're written, and catches detached work nobody is waiting on. Assumes the Bash tool runs bash.

- `shell-footguns` (skill) — catalog of shell traps and of ways a command's result can lie (masked exit status, a probe that cannot fail, `pgrep -f` matching the harness). Needs: nothing. Signals: you have had a command report success that turned out wrong; a wait loop returned instantly; Claude writes many shell scripts.
- `bash-footgun-gate` (hook, PreToolUse Bash and Monitor; **blocks the call**) — blocks commands that fail silently, each rule with its reason (`tee` masking an exit status, `grep -q` under pipefail, `pgrep -f`, `ssh host bash -s` stdin, bare `vault kv get`, `docker rm` keeping volumes, and others). Needs: nothing. Signals: you run Bash-heavy sessions, ssh, kubectl, vault or containers. Some rules assume the author's tools; adapt or delete rules you do not want.
- `detached-work-gate` (hook, Stop; **holds the end of a turn once per session**) — if the session detached work with `nohup`, `setsid` or `disown` and never armed a waiter, says so before ending. Needs: nothing. Signals: you have had to come back and ask "is that finished?" after a background job.
- `script-lint` (hook, PostToolUse Write/Edit; advisory, never blocks) — runs the bash-footgun rules over a shell script file just written; advisory only. Needs: nothing. Signals: Claude writes `.sh` files for you.

### secret-guard

Redacts secrets from Bash and Read output before they reach the model, using gitleaks plus extra rules.

- `secret-redact` (hook, PostToolUse Bash and Read; advisory, never blocks) — strips credential values from tool output before they reach context. Needs: gitleaks on your `PATH` or in `~/.local/bin`; without it only the pass that redacts values it saw fetched from a secret store runs. Signals: you work near vault, kubectl, cloud CLIs, `.env` files; a secret has ever appeared in a transcript.

### research

Web searches that find the answer: query construction, reading a bad result set, and a gate that loads the method first.

- `search-craft` (skill) — build, diagnose and iterate web search queries; tells whether the query, the index or the question is at fault. Needs: a search tool (WebSearch, SearXNG); `sx.py` and `instance.md` are for a SearXNG setup. Signals: transcripts show WebSearch calls, especially runs of reworded queries.
- `search-craft-gate` (hook, PreToolUse WebSearch; **blocks the call**) — blocks the first search of a session and the fourth, until `search-craft` has been loaded. Needs: the `search-craft` skill (same plugin). Signals: same as the skill.

### delegation

Subagent fan-outs that stay affordable: briefs, a model named per agent, depth limits, a checkout shared safely with agents and other sessions.

- `fanout-craft` (skill) — how to brief subagents, choose a model per agent, keep depth shallow and collect results. Needs: subagent use; a Max plan or similar if you fan out wide. Signals: transcripts show Agent spawns; you have hit a rate limit or a surprising bill after a fan-out.
- `model-golf` (skill) — compare models, prompts or effort levels on your own tasks with honest grading and cost. Needs: `claude -p` runs and some budget. Signals: you are deciding which model subagents should use.
- `agent-depth-gate` (hook, PreToolUse Agent; **blocks the call**) — stops a subagent tree recursing past a chosen depth (default: depth-2 agents may not spawn). Needs: nothing. Signals: subagents in your transcripts spawn their own subagents.
- `shared-checkout-backstop` (hook, Stop; **holds the end of a turn once per session**) — reports a repo you do not own left on a non-default branch. Needs: git. Signals: you run several Claude sessions, or edit in the same clone Claude works in.
- `spawn-model-gate` (hook, PreToolUse Agent; **blocks the call**) — refuses a spawn that names no model, an `opus` spawn whose prompt carries no `[opus: <reason>]`, and a Fable-model tree. Needs: nothing. Signals: you fan out and your subagents inherit the expensive default. Adapt: the Fable rule is the author's cost policy.
- `subagent-digest` (hook, SubagentStop; advisory, never blocks) — appends each finished subagent's final message to a durable log so completed-but-uncollected work is findable. Needs: nothing; costs no tokens. Signals: you have lost track of what a subagent concluded after the parent died or compacted.

### config-care

Keep a Claude Code setup lean: a drift report at session start (plus an optional monthly sweep), always-on load pruning, and audits of skills that have grown long.

- `always-on-prune` (skill) — decide which loading tier each piece of instruction text belongs in and move it to the cheapest one that still delivers it. Needs: a non-trivial `~/.claude/CLAUDE.md` or memory set. Signals: many `@import`ed memory files; context feels heavy at session start.
- `config-hygiene` (skill) — reports drift in a Claude Code setup: outgrown memory indexes, skills carrying instance data, docs their directory has moved past, unregistered hooks; reports, never edits. Needs: python3; an optional systemd timer is included. Signals: you have a memory directory and several skills of your own.
- `skill-golf` (skill) — audit one skill or memory file you own: which rules change behaviour, which can be cut. Needs: nothing; measuring uses `claude -p`. Signals: you wrote skills or memories and they have grown.
- `hygiene-sessionstart` (hook, SessionStart; advisory, never blocks) — runs the fast hygiene checks and surfaces drift into context; silent when clean. Needs: the `config-hygiene` skill (same plugin). Signals: same as `config-hygiene`.

### memory-discipline

Opinionated memory rules: refuses memory notes that are neither user/feedback nor carry a check, catches memory written from Bash, nudges lessons into the right home. Pair with stances/rules/memory-write-discipline.md.

- `memory-bash-write-backstop` (hook, Stop; **holds the end of a turn once per session**) — reports memory or skill files that changed this session without a Write/Edit call that explains it (the writes a PreToolUse gate cannot see). Needs: nothing. Signals: same as `memory-write-gate`.
- `memory-write-gate` (hook, PreToolUse Write/Edit; **blocks the call**) — refuses a write to `~/.claude/memory/*.md` or a project memory file unless the note is `type: user` or `type: feedback`, or carries a `check:` probe; Claude Code's own `project` and `reference` notes are refused until they carry one. Also refuses an edit that removes a `check:`. Unlike every other hook here it fails closed: an unreadable payload or a missing `python3` blocks the write. Needs: nothing; pairs with the `memory-write-discipline` rule in `stances/rules/`. Signals: you keep memory files and Claude writes to them.
- `route-lesson-gate` (hook, Stop; **holds the end of a turn once per session**) — when the session hit a streak of failed Bash runs and recorded no lesson anywhere, says so before ending. Needs: nothing; assumes you want lessons routed into memory or skills. Signals: you keep memories or skills and keep re-teaching the same trap.

### config-transfer

Move Claude Code config between your own machines, or across a trust boundary as a scrubbed bundle the other side imports by function.

- `claude-config-export` (skill) — package skills, memories and hooks into a scrubbed bundle for another trust domain (work machine, friend, public). Needs: gitleaks for the sweep. Signals: you keep a work and a home setup, or want to share yours.
- `claude-config-import` (skill) — merge such a bundle into this machine by function rather than duplicating. Needs: a bundle. Signals: you received one.
- `claude-fleet-sync` (skill) — mirror `~/.claude` across machines you fully control. Needs: ssh to your other hosts. Signals: you use Claude Code on more than one machine and they drift.

### continuity

Survive compaction: the date and time on every prompt, a context-size nudge to write a handoff, a snapshot before compaction and read back after.

- `postcompact-handoff` (hook, SessionStart after compaction; advisory, never blocks) — points the fresh post-compaction context at what the snapshot wrote; silent when there is nothing. Needs: `precompact-snapshot` (same plugin). Signals: same.
- `precompact-snapshot` (hook, PreCompact; advisory, never blocks) — writes machine-observable working state (uncommitted work, running agents, snapshot hash) to disk before compaction. Needs: git helps. Signals: you hit compaction in long sessions and lose track of state afterwards.
- `prompt-clock` (hook, UserPromptSubmit; advisory, never blocks) — stamps the wall clock and the gap since your previous message on every prompt, and nudges once at 300k and 450k tokens of context. Needs: nothing. Adapt: the token thresholds (`TIERS` in the script) are absolute counts; tune them to your window and budget. Signals: Claude guesses at elapsed time ("that was hours ago"); long sessions that outlive a day.

### k8s-ops

Kubernetes runbooks from a homelab: triage, sizing, secrets, storage, ingress/TLS, Talos, Flux, CloudNativePG, cert renewal, Grafana dashboards.

- `cluster-cert-renew` (skill) — check and renew Talos/Kubernetes admin certificates. Needs: Talos, talosctl, kubectl. Signals: "certificate has expired" or "provide credentials" errors on a Talos cluster.
- `cnpg-postgres-ops` (skill) — operate and recover a CloudNativePG cluster. Needs: CNPG and the `cnpg` kubectl plugin. Signals: you run CloudNativePG.
- `flux-gitops` (skill) — operate and debug Flux v2. Needs: Flux. Signals: `flux` or Kustomization/HelmRelease in your commands.
- `grafana-dashboards` (skill) — find, vet, build dashboards someone will read; query traps; dashboards as code. Needs: Grafana. Signals: you build Grafana dashboards.
- `k8s-ingress-tls` (skill) — expose a service with working TLS; walk DNS, entrypoint, ingress or Gateway, cert-manager. Needs: a cluster. Signals: ingress or cert-manager work.
- `k8s-resource-sizing` (skill) — CPU/memory requests and limits before and after usage data exists. Needs: a cluster; Prometheus for the data-driven half. Signals: OOMKilled or throttling in your transcripts.
- `k8s-secrets` (skill) — secrets in a GitOps repo: SOPS/age, external-secrets, sealed-secrets, key rotation. Needs: a GitOps cluster. Signals: you use SOPS or Flux.
- `k8s-storage-ops` (skill) — PVC won't bind, operator (Rook-Ceph, Longhorn) unhealthy, expansion stuck. Needs: a cluster with persistent storage. Signals: kubectl plus PVC or CSI problems.
- `k8s-triage` (skill) — diagnose a broken cluster from kubectl: crashing, pending, stuck pods, endpoints, NotReady nodes. Needs: kubectl and a cluster. Signals: you run kubectl in Bash commands.
- `talos-ops` (skill) — operate, upgrade and debug Talos Linux nodes and machine config. Needs: talosctl. Signals: you run Talos.

### linux-workstation

Immutable bootc/OSTree RHEL-family workstations: installing software, pinned-version scans, LUKS with TPM unlock, NVIDIA driver failures.

- `bootc-version-scan` (skill) — scan git repos for pinned versions (base images, `ARG *_VERSION`, Galaxy roles) that fell behind upstream, and push findings to a webhook. Needs: git repos with pins; a webhook for the push. Signals: you pin versions in Dockerfiles or Ansible.
- `bootc-workstation` (skill) — how an immutable bootc/OSTree RHEL workstation works and how to install software on it. Needs: such a host. Signals: you run bootc, rpm-ostree or Fedora Atomic-style hosts.
- `linux-gpu-troubleshoot` (skill) — NVIDIA driver and freeze failures on RHEL-family and bootc desktops. Needs: such a machine. Signals: you run NVIDIA on el9 or Fedora and have had freezes after kernel updates.
- `luks-tpm-recovery` (skill) — restore TPM2-backed LUKS auto-unlock after a firmware or Secure Boot change. Needs: a LUKS+TPM host. Signals: a machine prompts for a passphrase at every boot.

## Stances

Opinions, not tools. Each file in `stances/always-on/` is copied into `~/.claude/memory/` and
`@`-imported from `~/.claude/CLAUDE.md` by `stances/install.sh`; each costs context on every
request. Delete what you disagree with. Several are written in the first person of one operator;
change the quoted details to yours.

### always-on

- `pushback-not-hedging` — give a verdict and defend it instead of a both-sides survey. Needs: nothing. Signals: you ask for opinions or recommendations; you have complained about hedging.
- `hesitation-means-check-the-framing` — when you circle back on a choice, re-check the axis before re-selling the recommendation. Needs: nothing. Signals: you correct Claude mid-turn with a different framing.
- `prefer-subtraction` — do the minimum that fixes it; resist added guardrails, fallbacks and comments. Also states code-design taste (service locators, small functions, no regex over natural language); delete that paragraph if you disagree. Needs: nothing. Signals: diffs where Claude added more than you asked; accreted rules.
- `verify-dont-anchor` — an assumption is not a check; null results are not negative findings; list of probe traps. Needs: nothing. Signals: Claude has reported something verified that was not; a probe returned zero for the wrong reason.
- `distill-dont-dump` — docs should state the decision, not the deliberation. Needs: nothing. Signals: you have Claude write docs, ADRs or READMEs.
- `knowledge-routing` — decide where a fact lives by what would make it wrong (skill, doc beside the code, keyed data file, global memory). Needs: nothing. Signals: you keep memories, skills and docs and they overlap.
- `route-lessons-yourself` — capture a lesson in the same breath as the fix. Needs: nothing; points at `route-lesson-gate` for enforcement. Signals: you have had to say "we should capture this".
- `shell-gotchas` — Bash tool shell is bash, remote `ssh host '...'` is zsh; scripts go in files. Needs: `CLAUDE_CODE_SHELL` set to bash is the premise. Adapt: delete the zsh half if your remotes are bash. Signals: you ssh from Claude; you write multi-line shell.
- `repo-llm-stance` — LLM-authorship policy is per repo; some repos want the LLM as advisor only. Needs: nothing. Adapt: the named example is one repo; list yours. Signals: you maintain a repo with a no-AI-code stance.
- `issue-writing-style` — before drafting an issue under your name, load your voice reference; never invent a discovery story. Needs: the `bug-hunt` skill, whose voice section says how to derive your reference. Signals: you file issues or bug reports with Claude's help.
- `skill-fanout-is-authorized` — standing permission to fan out subagents when needed, readers wide and writers few. Needs: subagents; `fanout-craft` for the method. Signals: transcripts show Claude asking permission before spawning agents, or silently going serial.
- `spend-the-weekly-pool` — plan work to use the whole weekly allowance. Needs: a flat-rate plan with a weekly reset (Max). Adapt: wrong on pay-per-token billing; delete it there. Signals: you are on a Max plan and routinely end the week with budget left.
- `no-fabricated-certainty` — reports and checks must render missing data as unknown, not as a confident value. Needs: nothing. Signals: you build dashboards, reports or gates.
- `calibrate-to-the-user` — explain at the level of the user's real familiarity per topic, not Claude's; the file has a section for you to fill in your own calibration points. Needs: nothing, but only useful once you fill in the calibration points. Signals: you are expert in some areas and a beginner in adjacent ones; Claude's explanations are pitched wrong.
- `stateless-calls-cant-keep-a-rate` — a prompt run fresh each time cannot honour "rarely"; decide the rate in code. Needs: nothing. Signals: you write prompts that run as repeated independent calls (agents, bots, voice assistants).
- `print-names-not-values` — print names and set/empty/hash for config and secrets, never values. Needs: nothing; `secret-redact` is the backstop. Signals: you dump env, kubeconfig, vault or cloud config in sessions.
- `assert-scripted-edits` — use Write/Edit rather than Bash for file changes; assert anchors in scripted edits. Needs: nothing. Adapt: overrides auto mode's "prefer Bash for file changes"; delete if you want that. Signals: edits that silently no-op'd or deleted lines.
- `preserve-before-destroying` — make irreversible steps reversible first; `mv` not `rm`; separate the check from the act. Needs: nothing. Signals: you run destructive commands against live systems.
- `config-writes-replace` — many config APIs replace rather than merge; read, change one field, write back, re-read and count. Needs: nothing. Signals: you use vault, kubectl apply, az, Graph or similar from Claude.
- `search-read-the-failure` — load `search-craft` before non-trivial searches; good results without the answer mean the question is malformed. Needs: the `search-craft` skill (research plugin). Signals: WebSearch in your transcripts.
- `dont-bury-asks-or-answers` — give each ask its own visual anchor and close on the ask. Needs: nothing. Adapt: it records one person's reading pattern; rewrite for yours. Signals: you miss questions Claude buried in prose.
- `finish-it-dont-hand-back-a-plan` — do not end a turn with "next I'll do X" when X could be done now. Needs: nothing. Signals: you have returned to a session that stopped at a plan.
- `assume-the-checkout-is-shared` — commit with `--only`, never checkout or stash in a clone you do not own, use worktrees. Needs: git. Signals: several Claude sessions, or you and Claude, in one clone.
- `match-existing-house-style` — read sibling artifacts and copy exact values before adding another. Needs: nothing. Signals: new pages or files that look foreign beside their siblings.
- `size-test-workloads-to-node` — size test workloads against node headroom, not container limits. Needs: a shared Kubernetes cluster. Adapt: written for modest worker nodes. Signals: you run test workloads on a cluster that carries real services.
- `headless-browser-in-a-container` — render HTML you produce and look at it; no browser on the host is not a stopping point. Needs: `headless-render` for the method. Signals: Claude produces HTML you view; you work on hosts without a browser.
- `log-what-happened` — unattended jobs log start, finish, counts and failures as one-line key=value; pick stdout, database or file by who reads it back. Needs: nothing. Adapt: written around Loki and Alloy. Signals: you build cron jobs, workers or services.
- `herdr-peer-sessions` — new sessions you should track are herdr agents, not `claude --bg` workers. Needs: the herdr terminal harness (`HERDR_ENV=1`). Signals: you run Claude Code inside herdr.

### on-demand

Not imported always; load when relevant (project memory, or paste into a session).

- `content-is-king-not-proxies` — judge which duplicate is better by content, not size, filename or date. Needs: nothing. Signals: you curate media or documents.
- `ground-claims-with-a-cold-agent` — before acting on a non-trivial claim, have a fresh agent check it against the artifacts. Needs: subagents. Signals: Claude's confident conclusions have been wrong.
- `code-design-stances` — one author's code-design preferences beyond `prefer-subtraction`: decoupling patterns, help most where the user is weakest (often tests), no CI gates on doc wording, comments generous on APIs only. Needs: nothing; `agentic-engineering` holds the method. Adapt: preferences, delete what does not match yours. Signals: you want opinionated defaults for code structure; skip if you have your own.
- `skill-authoring-craft` — skills on live systems script the edges (gather, judge, apply) and record no-op verdicts. Needs: nothing. Signals: you write skills that touch live systems.
- `subagent-paths-prime-results` — anything handed to a subagent, including output paths, is part of its prompt. Needs: subagents. Signals: transcripts show subagents spawned with descriptive output paths.
- `ui-copy-not-claude-register` — UI copy should be terse labels, not assistant voice. Needs: nothing. Signals: you build UI with Claude-written strings.
- `user-discuss-dont-thrash` — on open-ended design questions, converge on one position instead of re-pitching. Needs: nothing. Signals: you have complained about Claude re-searching and re-recommending after every remark.
- `user-forcing-function-style` — an observation about one operator who runs on automation rather than willpower; confirm it before adopting. Needs: nothing. Signals: manual recurring steps you agreed to and quietly stopped doing.

### rules

- `memory-write-discipline` — path-scoped rule (applies when editing files under `.claude/memory`) on how to write a memory. Needs: nothing; `memory-write-gate` enforces it. Signals: you keep memory files.

### prompts

- `cut-llm-cruft` — paste-in prompt: scan a whole repo for LLM-generated cruft and propose cuts without deleting. Needs: nothing. Signals: a repo that agents have been building for a while.
